1. The Architectural State Restoration Asymmetry

In a homogeneous system, saving a task's state means dumping general-purpose registers to Non-Volatile Memory (NVM). In a heterogeneous system, migrating a half-executed task from a power-hungry core to an ultra-low-power core—or offloading it to a hardware accelerator—creates an architectural mismatch. [[1](https://dl.acm.org/doi/fullHtml/10.1145/3360285), [2](https://www.mdpi.com/2079-9292/14/6/1191), [3](https://arxiv.org/abs/1907.00271)]

- **The Gap:** Traditional schedulers do not know how to handle **asymmetric context serialization**. Schedulers lack a unified execution model to translate the register state, pipelines, and cache footprints of an active accelerator or "big" core into a format that a "little" core can resume mid-computation after a power failure.

2. Double-Ended Non-Linear Optimization (Energy vs. Compute Capability)

Heterogeneous scheduling traditionally uses Directed Acyclic Graphs (DAGs) to map tasks to processors based on execution time. However, in intermittent systems, both the **incoming energy supply** and the **core efficiency** are highly dynamic and non-linear. [[1](https://dl.acm.org/doi/fullHtml/10.1145/3467894), [2](https://arxiv.org/html/2603.23249v2), [3](https://ieeexplore.ieee.org/document/11637933/), [4](https://www.mdpi.com/2079-9292/14/6/1191)]

- **The Gap:** There is no mathematically sound runtime framework that simultaneously solves for both processor capabilities and real-time energy harvesting constraints. Current schedulers cannot dynamically calculate whether it is better to wait and harvest energy to run a task on a fast, power-hungry accelerator, or to execute it immediately using slow, highly inefficient serial software loops. [[1](https://www.mdpi.com/2079-9292/14/6/1191), [2](https://ieeexplore.ieee.org/document/11637933/)]

3. Accelerator Warm-up and "Cold-Boot" Waste

Hardware accelerators (like neuromorphic chips or custom cryptographic blocks) provide high energy efficiency _per operation_. However, they require a significant power injection just to boot up, initialize internal weights, and stabilize power rails. [[1](https://cs.stanford.edu/~keshav2/gavel.pdf), [2](https://www.mdpi.com/2079-9292/14/6/1191)]

- **The Gap:** Schedulers do not factor in **peripheral configuration overhead**. If a power failure occurs immediately after an accelerator finishes warming up but before it executes the workload, the system enters an infinite "boot loop" where energy is wasted exclusively on hardware initialization. Current scheduling heuristics lack the granular awareness to evaluate accelerator start-up states against capacitor levels. [[1](https://www.researchgate.net/publication/361729293_An_Energy-Aware_Task_Scheduler_for_Energy-Harvesting_Batteryless_IoT_Devices), [2](https://dl.acm.org/doi/fullHtml/10.1145/3467894), [3](https://www.mdpi.com/2079-9292/14/6/1191)]

4. Heterogeneous Memory Bank Wear and Energy Variation

A heterogeneous system often uses multiple memory layers (e.g., high-speed volatile SRAM, low-power non-volatile FRAM, and high-density Flash). Writing a checkpoint to Flash requires orders of magnitude more energy than writing to FRAM. [[1](https://www.youtube.com/shorts/FIfqxivjuT4), [2](https://dl.acm.org/doi/fullHtml/10.1145/3360285)]

- **The Gap:** Schedulers treat memory as a monolithic entity. There is a clear gap in **memory-topology-aware scheduling**, where the scheduler actively routes state checkpoints to different physical memory media based on the real-time volatility of the ambient energy harvester. [[1](https://www.youtube.com/shorts/FIfqxivjuT4)]

5. Multi-Source Harvester Cross-Talk & Co-Scheduling

Modern batteryless devices are moving toward multi-source harvesting (e.g., combining solar panels with RF harvesters). Each source provides energy with drastically different frequencies, voltages, and bursts. [[1](https://www.sciencedirect.com/science/article/pii/S2405959523000541), [2](https://dl.acm.org/doi/fullHtml/10.1145/3467894)]

- **The Gap:** Schedulers are historically designed for a single capacitor tied to a single energy harvester. Schedulers lack the policy engines required to **co-schedule hardware resources with energy inputs**, failing to map specific high-burst tasks to RF bursts and background baseline tasks to slow solar inputs. [[1](https://repository.uantwerpen.be/docstore/d:irua:13921), [2](https://dl.acm.org/doi/fullHtml/10.1145/3467894)]
